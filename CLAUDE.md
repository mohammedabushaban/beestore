# BeeStore — Project Memory

## Project Summary
BeeStore is a **v3-Lite** browser-only Arabic RTL accounting & inventory system for one children's clothing shop on **one phone**. It is delivered as an installable offline PWA from a free static HTTPS host (currently GitHub Pages; Cloudflare Pages is the commercial-safe alternative). Data lives in IndexedDB; the JSON folder mirror is an optional desktop-only extra. **Never open `index.html` via `file://`** — it is no longer a supported target. Local dev: `python3 -m http.server 8080` then `http://localhost:8080/`. Tests: `node --test --test-concurrency=1 tests/*.js` (currently 219; serialized so the 50k-invoice perf assertion is not measured while sibling test files run). After any app-shell change: `node scripts/build-sw-list.js`. **L1–L10 are implemented:** L2 keeps master data + the current and previous `memoryWindowMonths` in memory, reads older months lazily through IndexedDB date indexes (300-doc LRU + top progress bar), and serves dashboard/reports from a materialized `meta.summary` updated in the same transaction. L4 adds day locks, a four-step cash-drawer closing, signed cash differences in P&L, a Day Report, the Days page, dashboard day cards and Day mode. L5 adds owner/cashier local profiles, PBKDF2 PIN, auto-lock, a cashier allow-list in the facade, response stripping, and an audit profile. L6 adds large font and receipt-text sharing. L7 builds a read-only accountant ZIP (Arabic PDF, XLSX, BOM CSV, checksummed manifest) via dependency-free ZIP/XLSX/PDF writers and a shared CloudTarget. L8 expands the integrity check to 16 checks (closed-day recomputation, drawer balance, cash adjustments, stale days, backup, storage, clock). L9 adds the Arabic owner guide and upgrade/future docs. L10 is verified: Node/browser suites green; physical-phone checks remain documented as unverified. **v5 A1 is now implemented:** `chartOfAccounts` + append-only `journalEntries`, seeded v5 chart, legacy links, gapless JE numbering, day/month locks, exact reversals, trial balance and read-only invariant checks (`schemaVersion 4`, `dbVersion 7`). **v5 A2 is now implemented:** authoritative tracked inventory value (`valueMinor` per variant, `valueChangeMinor`/`valueAfterMinor` per movement), exact largest-remainder allocation, and inventory-side journal postings for sale COGS, sale returns, purchases, purchase returns, opening stock, adjustments/stocktakes and cost revaluation (`schemaVersion 5`, `dbVersion 7`). Sale revenue/cash/AR, purchase payments and every other cash-side posting remain A3 work. Documents and reports are **not yet journal-derived** — that cut-over is A3; A2 posts only inventory-side events.

## Architecture Overview

**Layers** (bottom → top):
- `core/` — utilities: namespace, config, money (minor units + largest-remainder `allocate`), dates (local YYYY-MM-DD), ids, validate, errors, v5 `chartSeed` (pure chart planning)
- `storage/` — repository interface + storage policy + append-only journal policy, `memoryRepository` (tests), `idbRepository` (browser, memory window + lazy indexed reads), pure `summary.js` (materialized totals/month buckets), `fileSync` (JSON mirror + backups), `migrations`
- `services/` — **all business logic**, pure JS, no DOM/IndexedDB/window (except the browser-only `pwa.js` and `snapshots.js`). Depend only on repository interface. `posting.js` is the shared v5 inventory-side posting layer.
- `api/api.js` — thin facade `BeeStore.api.<namespace>.<method>` returning `{ok, data|error}` envelopes
- `ui/` — router, components, dialogs, print helpers, first-run wizard, keyboard shortcuts, camera scanner
- `pages/` — one file per page, renders into `#page-content`
- `services/pwa.js` — SW registration, update banner, install prompt/guide, persistence, safe-update gate
- `services/snapshots.js` — separate IndexedDB (`beestore-snapshots`) for pre-migration snapshots (last 10)
- `sw.js` + `scripts/build-sw-list.js` — explicit app-shell precache list + content-hash `CACHE_VERSION`
- `manifest.json` + `icons/` — Arabic RTL standalone PWA identity

**Global namespace**: `window.BeeStore` (IIFE-wrapped files, classic `<script>` tags, no ES modules)

**Script load order** (index.html): core (`chartSeed.js` after errors) → storage → services (`accounts.js` then `chartOfAccounts.js`; `periods.js` then `journal.js` then `posting.js`; `zip.js`, `xlsx.js`, `monthReviewPdf.js`, `cloudTarget.js`, `accountingPackage.js` before `backup.js`; `auth.js` and `clockGuard.js` before the API) → api → ui (`ui/lock.js` with the other UI files; `ui/backupUI.js` after dialogs) → pages → demo → `services/pwa.js` → `app.js`. `services/snapshots.js` loads with the services.

## Golden Rules (never break)
- Money = integer minor units (agorot/cents). Use `BeeStore.money` only.
- Business dates = local `YYYY-MM-DD` strings. `dates.today()` uses local date parts, **not** `Date.toISOString()`.
- **The journal is append-only.** Never `put`/`remove` `journalEntries`; post via `journal.post(tx, …)`/`append` and void by exact reversing entries. The repository throws `APPEND_ONLY`; `importAll` is the only restore bypass.
- **Every journal entry must balance exactly** (integer debits = credits) and use existing, active chart accounts; never plug a difference. JE numbers come only from `meta.counters.journal` and stay gapless.
- **The chart is the economic identity; legacy `accounts` are detail records.** Link via `chartAccountId`; never duplicate balances. System chart accounts cannot be renamed/deactivated/deleted; no chart account is ever hard-deleted.
- **Tracked inventory value is authoritative.** Each variant stores `valueMinor`; average cost is derived (`valueMinor ÷ quantity`). Every stock movement stores `valueChangeMinor`/`valueAfterMinor` even when no posting occurs. Remove exact tracked value (the final unit takes the remainder); never recompute value as `quantity × average cost` when posting.
- **A2 posts the inventory side only.** Sale COGS, sale-return restock, purchase net value, purchase-return carrying-value difference, opening stock, adjustments/stocktakes and cost revaluation go through `BeeStore.posting`; revenue/cash/AR, supplier payments and other cash-side postings stay document-only until A3. A posting helper must no-op only when journal/chart are absent, never skip a missing system account.
- **Existing reports stay document-derived until A3.** A1 adds the ledger in parallel; do not silently switch a report to the journal before the parity cut-over.
- Every posting operation = **one** `repo.transaction(fn)`.
- `assertPeriodOpen(date)` inside every posting transaction (v2).
- `assertDayOpen(date)` inside sales, sale voids, returns, receipts/payments, cash expenses, transfers, withdrawals and capital movements (L4). Unpaid purchases, payroll accrual and stock adjustments stay allowed. `assertCashDayOpen` only blocks expenses paid from the cash drawer.
- No hard deletes: `status: "void"` / `active: false`.
- Escape all user text: `textContent` or `BeeStore.ui.escapeHtml()`.
- Arabic RTL throughout (`<html lang="ar" dir="rtl">`), Western digits.
- No `fetch` of local files, no CDN, no ES modules, no build step for the app.
- **No inline scripts or inline event handlers** (`onclick=` etc.) — CSP is `script-src 'self'`. Navigation uses delegated `[data-route]` clicks.
- **Never edit the generated `PRECACHE` / `CACHE_VERSION` in `sw.js` by hand.** Run `node scripts/build-sw-list.js`; `tests/test-sw.js` fails if stale.
- **Never call `skipWaiting()` during install.** The page sends `{type:'SKIP_WAITING'}` only after `BeeStore.pwa.applyUpdate()` passes the safe gate (empty POS cart, not saving, no **visible** dialog/wizard, no closing).
- The first-run wizard stays in the DOM hidden; visibility (computed `display`) matters, not mere presence.
- PWA data is origin-scoped (scheme + host + port), not path-scoped. Warn before any host/port change.
- Keep `index.html`'s CSP self-only: no third-party scripts, analytics, or remote fonts.
- **Backup integrity:** the SHA-256 `integrity.value` covers only `schemaVersion`, `meta`, `settings`, `collections` via `dataJson()`; never include `integrity` itself. A checksum mismatch must abort restore without touching data.
- **Never store the encryption passphrase.** It is used only in memory for AES-GCM/PBKDF2; losing it means losing that backup.
- **Restore is destructive:** always create a `pre-restore` snapshot first; if the snapshot fails, abort. Never overwrite live data before checksum/passphrase validation.
- `lastBackupRevision` records the post-bookkeeping `meta.revision`; do not treat the settings write that marks a backup as new business activity.
- **Permissions live in the facade, not the pages.** `api.js` has an explicit cashier allow-list; everything else is owner-only. Cashier responses must be stripped of cost/profit/margin keys, and `settings.profiles`/PIN fields must never leave the facade. Never expose a raw service when adding a new owner feature.
- **PINs are never stored in plain text** and never logged: only `{algorithm, iterations, salt, hash, createdAt}` (PBKDF2-SHA256, 210,000 iterations, 16-byte salt). Cashier limits (`cashierMaxDiscountPercent`, `cashierMaxReturnMinor`) are enforced again in `api.js`; UI checks are convenience only.
- **Clock guard:** backward >1 day vs the latest committed `meta.updatedAt`, or forward >30 days vs `meta.clock.lastSeenDate`, requires an owner confirmation for the day. Posting is blocked centrally; read-only `accountingPackage` is exempt.
- **Accountant package is read-only and generated locally.** ZIP is store-only (no compression library), XLSX is hand-written OOXML, PDF is canvas→JPEG in a minimal PDF. No CDN, no Drive API. Manifest SHA-256 must cover every file; open months must be marked «غير نهائي — الشهر مفتوح» everywhere.
- **Integrity recomputation** must pass `excludeClosingId` and the closing's recorded `cashDrawerAccountId`; otherwise the closing's own adjustment/transfer/withdrawal are double-counted.
- **Local roles are honest but limited:** no server, no remote wipe; they stop casual access, not a developer-tools user. Keep this caveat in README/CHECKLIST/owner guide.

## Short Recipes

**Add a page**: Create `js/pages/xyz.js` exporting `{ render(container) }`, register in `app.js _setupRouter()`.

**Add a service method**: Create/update `js/services/xyz.js`, bind repo in `api.js _bindServices()`.

**Add a facade method**: Add to `BeeStore.Api` in `api.js` returning `ok(data)` / `fail(code, msg)`.

**Add a report**: Add method to `ReportsService` (services/reports.js), expose in `api.js reports`, create page if needed.

**Add a settings field**: Add to `DEFAULT_SETTINGS` in `services/settings.js`, persist via `settings.save()`.

**Add data-model field + migration**: Add field in service `create()`, bump `schemaVersion` in `namespace.js`, add migration in `storage/migrations.js`.

## PWA / Deployment
- Hosting: GitHub Pages primary (repo already on GitHub; terms prohibit e-commerce/SaaS — BeeStore is an internal single-shop tool). Cloudflare Pages is the commercial-safe alternative. See `docs/DEPLOY_AR.md`.
- `manifest.json`: `start_url: "./"`, `scope: "./"`, Arabic/RTL, standalone, theme `#F5B700`.
- Icons: edit `icons/icon.svg` / `icons/icon-maskable.svg`, then screenshot with Chromium to PNG (no ImageMagick). Keep the SVGs as source.
- `sw.js` caches only the explicit app shell; never data, backups, downloads, or cross-origin requests. Navigation is cache-first with `index.html` fallback.
- `sw.js` deletes old `beestore-v3-lite-*` caches on activate and calls `clients.claim()`.
- Update UX: `تحديث متوفر` banner; apply only on tap; reload once via `controllerchange`; never lose an in-progress invoice.
- Persistence: `navigator.storage.persist()` on boot; result + usage/quota + install/offline/update status in Settings → البيانات.
- Off-device backup: Settings → النسخ الاحتياطي uses `navigator.share({files})` with a download fallback, SHA-256 integrity, optional AES-GCM encryption, and restore summary/warnings. The dashboard and PWA banner warn after 2 days with new activity (critical at 7). New phones can restore from the wizard.
- Pre-migration: `app.js` writes a snapshot to `beestore-snapshots` before `migrations.migrate`; abort migration if the snapshot fails. Restore also writes a `pre-restore` snapshot first.
- Tests: `tests/test-pwa.js`, `tests/test-sw.js`, `tests/test-snapshots.js`; browser checks cover offline start and safe update.
