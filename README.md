# بي ستور (Bee Store) — نظام المحاسبة والمخزون

**الإصدار:** `3.3.0-lite` — تطبيق ويب عربي (RTL) يعمل على **هاتف واحد**، **دون إنترنت**، ويُثبَّت على الشاشة الرئيسية.

---

## نظرة عامة

نظام متكامل لإدارة محل ملابس أطفال: المبيعات، المشتريات، المخزون، الزبائن، الموردين، المصاريف، الموظفون والرواتب، التقارير المالية، والإقفال الشهري.

منذ v3-Lite لم يعد التطبيق يُفتح من ملف محلي. هو **PWA** يُنشر على استضافة ثابتة عبر HTTPS:

- لا خادم تطبيق، ولا قاعدة بيانات على الإنترنت، ولا حسابات، ولا مزامنة.
- كل البيانات في **IndexedDB** داخل متصفح الهاتف.
- الاستضافة تعطي الملفات فقط؛ لا ترى بيانات المحل.
- التطبيق يعمل بعد التحميل الأول دون إنترنت.

> **لا تفتح `index.html` بالنقر المزدوج.** رابط `file://` يمنع IndexedDB والتثبيت. استخدم رابط HTTPS المنشور، أو `http://localhost` أثناء التطوير.

## البدء السريع

### 1. افتح النسخة المنشورة

افتح رابط التطبيق على الهاتف (مثال: `https://<username>.github.io/<repo>/`). راجع **[دليل النشر العربي](docs/DEPLOY_AR.md)** لخطوات النشر الأولى والتحديثات.

### 2. ثبّت التطبيق

- **أندرويد (Chrome):** قائمة ⋮ → «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية».
- **آيفون (Safari):** زر المشاركة → «إضافة إلى الشاشة الرئيسية». يجب أن يكون Safari وليس متصفحاً داخل تطبيق آخر.
- **كمبيوتر (Chrome/Edge):** أيقونة التثبيت بجانب شريط العنوان.

يمكنك أيضاً الضغط على زر «تثبيت» في الشريط السفلي داخل التطبيق، أو فتح **الإعدادات → البيانات → دليل التثبيت**.

### 3. أول تشغيل

أدخل بيانات المتجر، ثم اختر «البدء بدون بيانات» أو «تحميل بيانات تجريبية». على الهاتف تُتخطّى خطوة مجلد البيانات تلقائياً (ميزة كمبيوتر فقط). في خطوة القفل ضع رقماً سرياً للمالك (4–6 أرقام)، ويمكنك إضافة رقم للكاشير لاحقاً.

### 4. تأكد من العمل دون إنترنت

افتح **الإعدادات → البيانات** وتأكد من ظهور:

- «التطبيق محفوظ على الهاتف ويعمل دون إنترنت» ✅
- «نسخة الكاش» مثل `beestore-v3-lite-xxxxxxxxxxxx`
- زر «طلب تخزين دائم» (اضغطه مرة واحدة؛ قد يرفضه المتصفح)

ثم جرّب وضع الطيران وأعد فتح التطبيق من الأيقونة.

> للروتين اليومي والشهري، والأدوار، وحزمة المحاسب، وطوارئ ضياع الهاتف: **[دليل المالك العربي](docs/OWNER_GUIDE_AR.md)**.

## المتصفحات المدعومة

| المتصفح | الحالة |
|---|---|
| Android Chrome | مدعوم (المسح بالكاميرا، التثبيت، أوفلاين) |
| iPhone Safari 14.3+ | مدعوم (المسح عبر ZXing، التثبيت من Safari) |
| Chrome / Edge على الكمبيوتر | مدعوم (مجلد بيانات تلقائي اختياري) |
| Firefox / متصفحات أخرى | يعمل أساسياً، لكن بعض ميزات التثبيت/المجلد قد لا تتوفر |

- **File System Access API** (مرآة `db.json` التلقائية) متاحة على Chrome/Edge للكمبيوتر فقط. الهاتف يعتمد على IndexedDB + النسخ الاحتياطي خارج الجهاز (L3).
- الكاميرا تتطلب HTTPS أو `http://localhost`.
- قارئ الباركود USB/Bluetooth يعمل كإدخال لوحة مفاتيح ولا يتأثر بالعمل دون إنترنت.

## الاستضافة

**الاختيار الأساسي: GitHub Pages** — لأن المستودع موجود على GitHub، ولا يحتاج حساباً إضافياً ولا خطوة بناء، ويدعم HTTPS والمسارات النسبية.

### شروط GitHub Pages (تحقق: 2026-10-24)

- موقع منشور بحجم 1 GB كحد أقصى، ومستودع موصى به 1 GB.
- نطاق ترددي 100 GB شهرياً (حد «لطيف»).
- 10 عمليات بناء في الساعة (لا ينطبق مع GitHub Actions).
- مهلة نشر 10 دقائق.

**قيود الاستخدام:** GitHub Pages ليس خدمة استضافة لمتجر إلكتروني أو موقع تجاري أو SaaS. بي ستور أداة محاسبية داخلية لمحل واحد، ولا يبيع عبر الإنترنت ولا يقدّم خدمة SaaS، والاستضافة لا تتعامل مع أي بيانات. إن أردت استخداماً تجارياً واضحاً أو تجنّب أي التباس، استخدم **Cloudflare Pages** أو **Netlify**.

- الصفحات من مستودع عام هي الأبسط؛ المستودع الخاص يتطلب عادةً خطة GitHub مدفوعة.
- لا تضع أسراراً أو بيانات عملاء في المستودع.

المرجع: <https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits>

### بدائل

- **Cloudflare Pages:** اربط المستودع، Framework preset = None، Build command فارغ، Output directory = `/`. HTTPS مجاني واستخدام تجاري مسموح (راجع حدود الخطة الحالية).
- **Netlify:** اسحب المجلد إلى <https://app.netlify.com/drop>، أو اربط Git للتحديث التلقائي.

**تحذير العنوان:** بيانات IndexedDB مرتبطة بأصل الموقع (المخطط + النطاق + المنفذ)، وليس بمسار المجلد. الانتقال إلى نطاق/منفذ/بروتوكول آخر ينشئ قاعدة فارغة. خذ نسخة احتياطية قبل أي انتقال. تغيير المسار على نفس النطاق لا ينشئ قاعدة جديدة، لكنه قد يشارك نفس البيانات مع مشروع آخر على نفس النطاق؛ استخدم نشراً واحداً.

## التحديث الآمن (PWA)

1. بعد أي تعديل: `node scripts/build-sw-list.js` لتوليد قائمة الكاش ونسخة جديدة.
2. شغّل `node --test --test-concurrency=1 tests/*.js` (يجب أن تنجح كلها).
3. ارفع إلى GitHub وانتظر النشر.
4. افتح التطبيق متصلاً بالإنترنت. سيظهر **«تحديث متوفر»**.
5. لا تحدّث أثناء فاتورة/حفظ/نافذة مفتوحة/إغلاق يومي. التطبيق يرفض ويظهر رسالة عربية.
6. اضغط **«تحديث الآن»**؛ يُعاد تحميل التطبيق مرة واحدة. البيانات المحفوظة لا تُحذف.

لا يفعّل الـ service worker النسخة الجديدة تلقائياً. لا يحدث `skipWaiting` إلا بعد طلب المستخدم ونجاح فحص الحالة الآمنة. بعد التفعيل يُحذف الكاش القديم فقط، ولا تُمس IndexedDB.

إذا لم يظهر التحديث: أغلق التطبيق وأعد فتحه، أو **الإعدادات → البيانات → التحقق من التحديث**. لا تمسح بيانات الموقع.

## البيانات والنسخ الاحتياطي

| المخزن | الاستخدام |
|---|---|
| IndexedDB `beestore-db` | كل بيانات المحل |
| IndexedDB `beestore-snapshots` | لقطات أمان محلية قبل تحديث مخطط البيانات (آخر 10) |
| Cache Storage `beestore-v3-lite-*` | ملفات التطبيق فقط (ليست بيانات) |

- **نسخة خارج الجهاز (L3):** الإعدادات → النسخ الاحتياطي → **نسخ ومشاركة** يفتح درج المشاركة (Drive/واتساب/بريد). إذا لم يدعم المتصفح مشاركة الملفات، يُنزّل الملف تلقائياً؛ انقله بعد ذلك خارج الهاتف. زر **تنزيل فقط** متاح أيضاً.
- **اسم الملف وبصمته:** `BeeStore-backup-YYYY-MM-DD-HHmm.json`، مع بصمة **SHA-256** تمنع استيراد ملف تالف أو معدّل.
- **تشفير اختياري:** كلمة مرور تُشتق منها مفاتيح AES-GCM (PBKDF2)؛ لا تُحفظ كلمة المرور. الاستعادة تطلبها وتتعامل مع الكلمة الخاطئة برسالة واضحة.
- **تذكير:** شريط متكرر في التطبيق ولوحة الرئيسية عندما يمر يومان على آخر نسخة مع وجود نشاط جديد، ويتحول إلى تحذير أحمر بعد 7 أيام. تُسجّل آخر نسخة في `lastBackupAt`، والمشاركة خارج الهاتف في `lastOffDeviceBackupAt`؛ التنزيل وحده يبقى على الهاتف حتى تنقله.
- **استعادة آمنة:** فحص البصمة، ملخص بالتاريخ وعدد السجلات وأحدث سجل، تحذيرات للنسخ الأقدم أو من جهاز آخر، **لقطة أمان داخلية تلقائية** قبل الاستبدال، ثم إعادة تحميل. النسخ القديمة بدون بصمة تُقبل مع تحذير.
- **هاتف جديد:** من معالج البدء اختر **استعادة من نسخة احتياطية** وحدد الملف؛ لا تحتاج إلى إعداد المتجر يدوياً.
- **مجلد بيانات تلقائي:** كمبيوتر Chrome/Edge فقط، مع نسخ موقوتة في `backups/`.
- **لقطات محلية:** تُنشأ تلقائياً قبل أي ترحيل لمخطط البيانات، وتظهر في **الإعدادات → البيانات** مع زر تنزيل.
- **عنوان المتجر:** إذا كان فارغاً يظهر تحذير في تبويب النسخ الاحتياطي؛ أضفه قبل النسخة النهائية حتى تظهر الفواتير بشكل صحيح.

> التخزين الدائم (`navigator.storage.persist`) يقلل احتمال حذف المتصفح للبيانات عند ضغط المساحة، لكنه **ليس نسخة احتياطية** ولا يضمن عدم الحذف. النسخة التي تبقى على الهاتف فقط ليست «خارج الجهاز» حتى تنقلها إلى Drive/واتساب/USB.

### خطوات النسخة الاحتياطية والاستعادة

1. **الإعدادات → النسخ الاحتياطي**.
2. اترك «تشفير بكلمة مرور» مغلقاً للنسخة اليومية السريعة، أو فعّله عند إرسال الملف عبر واتساب/بريد (كلمة المرور لا تُحفظ).
3. اضغط **نسخ ومشاركة** واختر Drive أو واتساب أو البريد. إذا لم تظهر نافذة المشاركة، سيُنزّل الملف؛ انقله خارج الهاتف.
4. على الهاتف الجديد: ثبّت التطبيق، افتحه، وفي معالج البدء اختر **استعادة من نسخة احتياطية**، أو من الإعدادات → النسخ الاحتياطي → **استعادة من ملف**.
5. راجع الملخص والتحذيرات، واكتب كلمة **استعادة** لتأكيد الاستبدال. تُنشأ لقطة أمان داخلية أولاً. إذا كانت النسخة من جهاز آخر، يصبح هذا الهاتف هو الأساس؛ توقّف عن العمل على الجهاز القديم بعد الاستعادة.
6. إذا نسيت كلمة مرور نسخة مشفرة فلا يمكن استعادتها؛ احتفظ بكلمة المرور في مكان آمن منفصل.

## الميزات الرئيسية

### نقطة البيع (POS)
- مسح بالكاميرا / قارئ USB/Bluetooth / بحث بالاسم / تصفية بالتصنيف
- دمج الأصناف المتطابقة، خصم سطر/فاتورة، دفع مقسم
- بيع آجل مع أقساط، طباعة A4 أو 80 مم
- إضافة صنف جديد من باركود غير معروف دون فقدان الفاتورة

### المخزون
- منتجات بأحجام وألوان، باركود تلقائي/يدوي مع منع التكرار
- قيمة مخزون متتبعة بالوحدة الصغرى ومتوسط تكلفة مشتق بلا انحراف تقريب
- تسوية، جرد، استيراد CSV، تنبيه مخزون منخفض
- صفحة «فحص سعر» للمسح السريع

### الحسابات والتقارير
- قائمة الدخل (P&L) بتكلفة متوسطة موزونة
- تقارير مبيعات، تقييم مخزون، ذمم بالتقادم، ميزانية مبسطة
- نواة محاسبية v5: دليل حسابات ودفتر يومية مزدوج القيد للإضافة فقط، مع ترحيل أحداث المخزون في A2 (انظر أدناه)
- إغلاق يومي موسّع (L4): مطابقة صندوق، معالج 4 خطوات، تقرير يوم، صفحة أيام، قفل اليوم
- مصاريف، رواتب، إقفال شهري (v2)
- تصدير CSV مع BOM للعربية

### أمان البيانات
- قفل التطبيق برقم سري (PBKDF2-SHA256 بملح عشوائي، 210,000 تكرار) مع قفل تلقائي بعد الخمول/الخلفية
- ملفان محليان: **المالك** و**الكاشير**، وحدود خصم/مرتجع للكاشير، وتدقيق يسجّل الملف المنفّذ
- قفل تبويب واحد (Web Locks API)
- حفظ تلقائي عند إغلاق التبويب
- ترحيل مخطط البيانات مع لقطة أمان تلقائية
- CSP صارم: سكربتات محلية فقط، بلا inline eval أو معالجات onclick
- تحديث آمن لا يقطع فاتورة

> **حدود الأدوار بصراحة:** بلا خادم، الحماية المحلية تمنع الوصول العابر (فتح الهاتف، رؤية التكاليف أو التقارير) ولا تمنع شخصاً تقنياً يستخدم أدوات المطوّر. لا يوجد **مسح عن بُعد** للهاتف المفقود. الحماية الحقيقية: قفل شاشة الهاتف + الرقم السري + نسخ احتياطية متكررة خارج الجهاز.

## الإقفال الشهري (v2)

1. من الترويسة اختر الشهر (◀ الشهر ▶). كل الصفحات تعرض نطاقه، والمُقفل يحمل شارة 🔒.
2. **ولّد المصاريف الشهرية** من تنبيه الرئيسية إن وُجدت.
3. **جهّز الرواتب وادفعها** من صفحة الموظفون والرواتب.
4. (اختياري) نفّذ **جرد المخزون**.
5. افتح **إقفال الشهور**: راجع قائمة الفحص وتقرير الشهر، ثم اضغط **إقفال الشهر** (نسخة احتياطية تلقائية قبل القفل).
6. الشهر المُقفل ممنوع تعديله؛ التصحيح يُسجَّل في الشهر الحالي، أو أعد فتح **آخر شهر مُقفل فقط** بتأكيد كتابي.
7. شراء البضاعة لا يُنقص ربح الشهر؛ الربح ينقص عند البيع. تقرير «الربح ⇄ النقد» يوضح الفرق.

## نواة المحاسبة v5 (A1–A3)

- **دليل الحسابات ودفتر اليومية (A1):** 37 حساباً نظامياً + حساب تسوية لكل طريقة دفع غير نقدية، دفتر مزدوج القيد **للإضافة فقط**، أرقام `JE-000001` بلا فجوات، قيود عكسية مطابقة، وأقفال اليوم/الشهر داخل الخدمة. لا حذف أو تعديل لقيد محفوظ؛ التصحيح بقيد عكسي.
- **قيمة المخزون المتتبعة (A2):** كل صنف يحمل `valueMinor` (قيمة المخزون الإجمالية)، والمتوسط يُشتق منها؛ كل حركة مخزون تحمل `valueChangeMinor` و`valueAfterMinor`. لا تُحسب القيمة عند الترحيل من `الكمية × المتوسط` بل تُستهلك بدقة، وآخر وحدة تأخذ الباقي.
- **الترحيل المخزني (A2):** تكلفة المبيعات، مرتجع المبيعات، صافي المشتريات، فرق مرتجع الشراء إلى `5030`، المخزون الافتتاحي إلى `3030`، التسويات/الجرد إلى `5020`، وتسوية التكلفة بين `1200` و`5030`. كل قيد داخل معاملة المستند ويتوازن بالوحدة الصغرى.
- **ترحيل المستندات (A3):** إيرادات المبيعات والذمم والدفعات المؤرخة، تحصيلات الزبائن مع رصيد `2030` للزيادة، مرتجعات البيع والاستبدال، المشتريات ودفعات الموردين، مرتجعات الشراء بالنمطين، المصروفات والموزّع، الرواتب والسلف، الملكية والتحويلات وفروقات الإقفال اليومي. كل قيد داخل معاملة المستند، والإلغاء/التعديل بقيد عكسي مطابق بتاريخ الأصل ثم إعادة ترحيل عند الحاجة.
- **الافتتاحيات وإعادة التشغيل (A3):** أرصدة الحسابات والزبائن والموردين والمخزون الافتتاحية إلى `3030`. الترحيل 5→6 يعيد حساب مستحقات الشراء ويعبّئ `appliedMinor` للتحصيلات القديمة؛ `posting.replayAll()` يعيد بناء قيود A3 الناقصة من مستندات ما قبل A3 دون تكرار، والإقلاع يشغّله عند الحاجة.
- **اعتماد تقارير الدفتر (A3):** `reports.parityReport()` يطابق P&L واللقطات وأرصدة الزبائن/الموردين والمخزون وفحص الدفتر. لا تتحول P&L/الميزانية إلى الدفتر إلا بعد اعتماد صريح عبر `approveJournal()` وبلا فروقات؛ `options.legacy` يبقي مسار المستندات للمراجعة.
- **ما لم يُرحّل بعد:** نطاق A4 (تسويات/عمولات البطاقات، المصروفات والدفعات غير المدفوعة، مكوّنات رواتب أعمق، الأصول الثابتة، الضريبة)، وتوزيع خصم فاتورة البيع على الأسطر (v4 M7)، وواجهة دفتر اليومية/دليل الحسابات (A6).

## الإقفال اليومي (v3-Lite L4)

الإقفال اليومي **ضبط للصندوق وليس فترة محاسبية**؛ الشهر يبقى الفترة. افتحه من **الرئيسية → إغلاق اليوم** أو صفحة **الأيام** أو **الحسابات → إغلاق اليوم**.

1. **ملخص اليوم:** المبيعات حسب طريقة الدفع (صافي المرتجعات)، الفواتير، المرتجعات النقدية، تحصيلات الزبائن، المصاريف النقدية، وحركات أخرى، والرصيد الافتتاحي والمتوقع في الصندوق.
2. **جرد النقد:** عدّاد بالفئات المضبوطة في الإعدادات، أو إدخال الإجمالي مباشرة. الفرق = المعدود − المتوقع. يمكن **الإقفال بدون جرد** ليوم منسي؛ فيُسجَّل بلا فرق صندوق.
3. **إخراج النقد:** إيداع في البنك أو سحب شخصي (ينشئ تحويلاً/سحباً حقيقياً في الحسابات)، والمتبقي يصبح رصيد افتتاح اليوم التالي. الفرق السالب يُسجَّل مصروف عجز، والموجب دخل زيادة، حتى يتساوى النقد الدفتري مع المعدود.
4. **التأكيد:** ملاحظة، ثم إقفال ذري واحد ينشئ كل السجلات المولّدة. بعدها يظهر **تقرير اليوم** مع طباعة A4/80mm ومشاركة ونسخة احتياطية.

قواعد أساسية:

- الأيام تُقفل **بالترتيب**؛ لا يُقفل يوم أحدث قبل الأقدم. اليوم المنسي يُقفل «بدون جرد» ثم يُفتح ما بعده.
- بعد الإقفال يُمنع البيع والمرتجع والتحصيل والدفع والمصروف النقدي والتحويل والسحب ورأس المال بتاريخ ذلك اليوم. المشتريات غير المدفوعة والرواتب المستحقة وتسويات المخزون تبقى مسموحة.
- **إعادة الفتح** متاحة لآخر يوم مُقفل فقط، وبعد التأكد من أن الشهر مفتوح. تُلغى السجلات المولّدة (تحويل/سحب/تسوية فرق) مع أثر تدقيق، ويبقى سجل اليوم بحالة `reopened` ثم يُعاد استخدامه عند الإقفال من جديد.
- **وضع اليوم:** اختر يوماً من منتقي الفترة (`?d=YYYY-MM-DD`) لعرض الصفحات في نطاق ذلك اليوم، مع شريط تحذير إذا كان اليوم مُقفلاً.

## القفل والأدوار المحلية (v3-Lite L5)

- **المالك** يرى ويعدّل كل شيء. **الكاشير** يستطيع إنشاء فواتير (خصم حتى `cashierMaxDiscountPercent`، افتراضي 10%)، تحصيل دفعات، عرض المنتجات والأسعار والمخزون، إنشاء مرتجع حتى `cashierMaxReturnMinor` (افتراضي ₪50)، رؤية ملخص يومه، وفحص السعر.
- الكاشير **لا يستطيع** رؤية التكلفة أو الربح، ولا فتح التقارير أو المصاريف أو الرواتب أو الحسابات أو الإعدادات أو النسخ أو الإقفال أو الإلغاء أو تعديل الأسعار/المنتجات أو تسويات المخزون.
- **التطبيق المركزي:** كل المنع و«تقليم» الاستجابات يحدث في `BeeStore.api` (قائمة سماح صريحة للكاشير + إزالة حقول التكلفة/الربح + إخفاء `profiles` و`pin`)، وليس في الصفحات.
- **القفل:** رقم 4–6 أرقام، يُخزَّن PBKDF2-SHA256 بملح 16 بايت و210,000 تكرار فقط. بعد 5 محاولات خاطئة يتأخر الإدخال 30 ثانية ثم يتضاعف حتى 15 دقيقة. القفل التلقائي بعد `autoLockMinutes` (افتراضي 5) أو بعد دقيقة في الخلفية.
- **تبديل الملف:** من شريط الملف الشخصي. عند فتح القفل بملف مختلف تُعاد الواجهة كاملة؛ الفاتورة قيد الإدخال لا تُفقد عند فتح نفس الملف.
- **التدقيق:** كل سجل تدقيق يحمل `profile` (owner/cashier)، وكذلك الفواتير والمرتجعات والاستبدالات (`createdByProfile`).
- **تنبيه الساعة:** إذا كان تاريخ الهاتف أقدم من آخر عملية محفوظة بأكثر من يوم، أو قفز للأمام أكثر من 30 يوماً، يظهر تحذير عربي مانع للتسجيل حتى يؤكد المالك صحة التاريخ. الفحص يتكرر في الواجهة المركزية، لا في الصفحات.

> **بصراحة:** لا خادم ولا مسح عن بُعد. الأدوار المحلية تحمي من الوصول العابر، لا من شخص تقني بأدوات المطوّر. للحماية الحقيقية: قفل شاشة الهاتف + رقم التطبيق + نسخ خارجية متكررة.

## حزمة المحاسب (v3-Lite L7)

من **إقفال الشهور** بعد اختيار الشهر:

- **مشاركة الحزمة / تنزيل الحزمة:** ملف ZIP واحد اسمه `BeeStore-YYYY-MM-Accountant-Package.zip` يحتوي:
  - `00-README.txt` عربي/إنجليزي مع تعريفات الأرقام.
  - `01-Month-Review.pdf` بتقرير الشهر العربي (صفحات صور آمنة للعربية).
  - `accounting.xlsx` بثماني عشرة ورقة (ملخص P&L، يومية مبيعات، بنود بتكلفة وهامش، مرتجعات، مشتريات، مصاريف، رواتب، صندوق، بنك/محافظ، أعمار ذمم، تقييم مخزون، حركات مخزون، ميزانية، تسوية ربح/نقد، إقفالات أيام، تسويات/إلغاءات، فحص سلامة).
  - `csv/` نسخة من كل جدول بترميز UTF-8 مع BOM (آمن للعربية في Excel).
  - `manifest.json` قائمة الملفات وأحجامها وبصمات SHA-256 ونتائج التحقق المتقاطع.
- **الشهر المُقفل نهائي.** الشهر المفتوح يحمل علامة **«غير نهائي — الشهر مفتوح»** في PDF والقراءة وورقة الملخص والبيان.
- **التحقق المتقاطع** داخل الحزمة: P&L = تقرير الشهر، Σ يومية المبيعات = صافي المبيعات (+ الضريبة)، رصيد الصندوق = كشف النقدية، تقييم المخزون = صورة الميزانية، مجموع فروقات الأيام = فرق الصندوق في P&L، وبصمات الملفات صحيحة.
- **المشاركة:** نافذة نظام المشاركة (Drive/واتساب/بريد) عبر `CloudTarget`، أو تنزيل مباشر إن لم يدعم المتصفح مشاركة الملفات. لا رفع سحابي مباشر من التطبيق.
- الحزمة **للقراءة فقط** للمحاسب؛ لا تعدّل بيانات التطبيق.

## سلامة البيانات والساعة (v3-Lite L8)

فحص السلامة في **الإعدادات → الصيانة** و**إقفال الشهور** أصبح 16 فحصاً، ويضيف:

- إعادة حساب كل يوم مُقفل من مستنداته ومقارنتها بالأرقام المجمّدة (بما فيها طرق الدفع، المتوقع، المعدود، الفرق، والمتبقي).
- رصيد الصندوق الحالي = متبقي آخر إقفال + كل الحركات اللاحقة.
- كل تسوية `cash_difference` نشطة تطابق إقفالها (المبلغ، التاريخ، الحساب)، ومجموعها الشهري يطابق فروقات الأيام.
- تحذير للأيام التي فيها حركة ولم تُقفل بعد أكثر من `unclosedDayWarningDays` (افتراضي 3).
- عمر آخر نسخة احتياطية، ونسخة خارج الجهاز، ونسبة مساحة المتصفح (تحذير عند 80% و90%).
- حالة حارس الساعة داخل نتيجة الفحص، مع منع التسجيل حتى التأكيد.
- الأخطاء تمنع إقفال الشهر، والتحذيرات لا تمنع لكن تظهر بوضوح.

## التطوير والاختبارات

لا توجد خطوة بناء للتطبيق نفسه (سكربتات كلاسيكية، بلا ES modules). لا يوجد `package.json`؛ كل الأوامر تعمل مباشرة بـ Node.

```bash
# خادم محلي (Service Worker يعمل على localhost)
python3 -m http.server 8080
# ثم افتح http://localhost:8080/

# بعد أي تعديل على ملفات التطبيق: أعد توليد قائمة الكاش
node scripts/build-sw-list.js

# كل الاختبارات (تسلسلي كي لا تتداخل قياسات الأداء)
node --test --test-concurrency=1 tests/*.js
```

- Node 24 موصى به.
- استخدم `--test-concurrency=1` عند تشغيل المجموعة كاملة؛ اختبار الأداء (50,000 فاتورة) يفشل هامشياً إذا قُسس أثناء تشغيل بقية الملفات على جهاز مزدحم. تشغيل الملف منفرداً يعطي الرقم الأدق.
- `tests/test-sw.js` يفشل إذا كانت قائمة الكاش أو نسخة الكاش لا تطابق الملفات الحالية — شغّل سكربت البناء.
- لا تستخدم `node --test tests/` مع هذا الإصدار من Node؛ استخدم `tests/*.js`.
- اختبار A2 في Node: `tests/test-inventory.js` (14 اختباراً: توزيع الباقي الأكبر، COGS الدقيق، خصومات المرتجع، فرق مرتجع الشراء، الإلغاء، التسويات، الترحيل 4→5، وعشوائية الثوابت).
- اختبار A3 في Node: `tests/test-postings.js` (11 اختباراً: الافتتاحيات، المبيعات والتحصيلات والزيادة، أوضاع المرتجع، مرتجع الشراء، المصروفات الموزّعة، الرواتب، الملكية/التحويل/إعادة فتح اليوم، وإعادة التشغيل والترحيل 5→6).
- اختبارات المتصفح (تحديث/أوفلاين) تحتاج Chromium وChromedriver محليين، وليست جزءاً من `node --test`.
- اختبارا L2 في المتصفح: `tests/idb-lazy.html` (نافذة الذاكرة، القراءة المفهرسة، الملخص، فهرس `variantDate`، الترقية v3→v6، مؤشر التحميل) و`tests/perf.html` (بذور 50,000 فاتورة و50,000 حركة مخزون وقياس الأهداف).
- اختبار L4 في المتصفح: `tests/ui-days.html` (بطاقات اليوم/أمس، جدول الأيام، معالج الإقفال، عدّاد الفئات، تقرير اليوم والطباعة، تقرير الشهر، إعدادات الصندوق).
- اختبار L7/L8 في المتصفح: `tests/ui-package.html` (حزمة مفتوحة/مُقفلة، PDF عربي عبر Canvas، 18 CSV بترميز BOM، بصمات manifest، مشاركة/تنزيل، رفض الكاشير، وفحص سلامة 16 بنداً).
- فحص L10 للأوفلاين: `tests/verify-offline.py` (Chromium + ChromeDriver + CDP): يقطع الشبكة بعد تثبيت الـ Service Worker، ويتأكد من فتح الواجهة من الكاش، قراءة البيانات من IndexedDB، حفظ فاتورة أثناء الانقطاع، وبقائها بعد إعادة تحميل ثانية. شغّله بعد `python3 -m http.server 8765` و`chromedriver --port=9515`.

### الأداء المقاس (L10، بعد L8)

القياس النهائي على Chromium بلا واجهة (سطح مكتب) مع 50,000 فاتورة و50,000 حركة مخزون وذاكرة نافذة شهرين (6,236 فاتورة داخل الذاكرة)، بتاريخ 2026-10-26:

|---|---|---|
| بدء بارد | ≤ 3,000 ms | 523 ms |
| حفظ فاتورة | ≤ 100 ms | 18 ms |
| الرئيسية | ≤ 1,000 ms | 276 ms |
| تقرير شهر داخل النافذة (2026-10) | ≤ 1,000 ms | 227 ms |

حجم القاعدة المقاس 37.1 MB. هذه أرقام بيئة تطوير سريعة (Chromium بلا واجهة، وسجل بذور متغيّر)، وليست بديلاً عن قياس هاتف فعلي متوسط؛ يبقى ذلك بنداً غير متحقق في L10.

## قرارات إضافية (Decisions)

- **الاستضافة:** GitHub Pages لأن المستودع موجود على GitHub ولا يحتاج حساباً/بناءً إضافياً، مع توضيح شروطها وبديل Cloudflare Pages للاستخدام التجاري. التفاصيل في `docs/DEPLOY_AR.md`.
- **الكاش:** قائمة ملفات صريحة داخل `sw.js` + بصمة SHA-256 كمفتاح كاش. لا `skipWaiting` تلقائي، ولا كاش لأي بيانات أو نسخ احتياطية أو طلبات خارجية.
- **CSP:** `script-src 'self'` بلا سكربتات مضمّنة أو `eval`. سُمح بـ `style-src 'unsafe-inline'` لأن الواجهة تضبط `style` ديناميكياً، مع إزالة كل معالجات `onclick` المضمّنة.
- **اللقطات:** قاعدة IndexedDB منفصلة `beestore-snapshots` (وليس داخل `beestore-db`)، بحد أقصى 10 لقطات، وتُنشأ قبل ترحيل المخطط. اللقطة ليست بديلاً عن نسخة خارج الهاتف.
- **الأيقونات:** ملفات SVG قابلة للتعديل هي المصدر، وPNG مولّد منها عبر Chromium (بدون ImageMagick).
- **الإصدار:** `3.3.0-lite` مع `schemaVersion = 6` و`dbVersion = 7` (الإصدارات 4–6 تضيف فهارس ومخزن `cashAdjustments`، والإصدار 7 يضيف `chartOfAccounts` و`journalEntries` ضمن v5 A1؛ v5 A2 يرفع مخطط المستندات إلى 5 لقيمة المخزون المتتبعة؛ v5 A3 يرفعه إلى 6 لإعادة حساب مستحقات الشراء و`appliedMinor` وربط إعادة التشغيل). النسخ الاحتياطي لا يغيّر المخطط.
- **نافذة الذاكرة (L2):** تُحمَّل البيانات الأساسية كاملة + مستندات الشهر الحالي والشهرين السابقين (`memoryWindowMonths = 2`). الأشهر الأقدم تُقرأ عند الطلب عبر فهارس التاريخ في IndexedDB، مع ذاكرة مؤقتة صغيرة (300 مستند) ومؤشر تقدّم غير حاجب. كل قراءات المستودع غير متزامنة، لذلك لم تتغير الخدمات.
- **ملخص مُجسَّم (Materialized Summary):** مجموع المبيعات والمشتريات والأرصدة والذمم والأقساط وP&L الشهري يُحدَّث داخل نفس معاملة الحفظ في `meta.summary`، فلا تمسح الرئيسية أو تقرير الشهر 50 ألف فاتورة. التصدير الكامل يقرأ الأشهر القديمة من IndexedDB دائماً.
- **نطاق البيانات:** IndexedDB مرتبط بأصل الموقع (المخطط + النطاق + المنفذ) وليس بمسار المجلد؛ لذلك الانتقال إلى نطاق/منفذ آخر يحتاج نسخة احتياطية واستعادة.
- **الإقفال اليومي (L4):** ضبط صندوق لا فترة محاسبية. كل يوم يُقفل بمعاملة واحدة تنشئ فروقات الصندوق (`cashAdjustments`) وتحويل/سحب النقد المأخوذ. الفرق السالب يزيد المصاريف والموجب يقللها في P&L. الأيام تُقفل بالترتيب، والمنسي يُقفل «بدون جرد»، وإعادة الفتح لآخر يوم مُقفل فقط مع إلغاء ناعم للسجلات المولّدة وأثر تدقيق.
- **حساب الصندوق:** `cashDrawerAccountId` افتراضي (أول حساب صندوق إن لم يُضبط)، و`defaultBankAccountId` يُقترح عند الإيداع، و`cashDenominations` تُضبط من الإعدادات → طرق الدفع وتُستخدم في عدّاد الجرد.
- **الأدوار المحلية (L5):** `auth.js` يخزّن لكل ملف `{algorithm, iterations, salt, hash, createdAt}` فقط، ويخفي كل حقل PIN من استجابات الواجهة. `api.js` يطبّق قائمة سماح صريحة للكاشير + إزالة حقول التكلفة/الربح + منع العمليات المالكية، مع استثناءات قراءة آمنة (الفاتورة وملخص اليوم). هذا حماية محلية صريحة، وليست أماناً ضد أدوات المطوّر.
- **حارس الساعة (L5/L8):** تراجع > يوم عن آخر مستند محفوظ، أو قفزة > 30 يوماً عن آخر يوم مفتوح، يوقف التسجيل حتى تأكيد المالك لتاريخ اليوم. الفحص مركزي في الواجهة، ويظهر أيضاً في فحص السلامة.
- **حزمة المحاسب (L7):** تُبنى محلياً في المتصفح من نفس مستندات التقارير. ZIP مخزّن بلا ضغط (كاتب/قارئ داخلي)، XLSX بكاتب مستقل بلا مكتبات، وPDF عربي عبر رسم Canvas ثم JPEG داخل PDF بسيط. لا مكتبة خارجية ولا CDN. الحزمة لا تكتب في قاعدة البيانات، ومحمية بقائمة المالك فقط في الواجهة.
- **فحص السلامة (L8):** إعادة حساب الأيام المُقفلة تستبعد مستندات الإقفال المولّدة نفسها (تسوية الفرق، التحويل، السحب) عبر `excludeClosingId`، وتستخدم حساب الصندوق المحفوظ مع الإقفال لا الحساب الحالي.
- **نواة المحاسبة v5 A1:** دليل الحسابات هو الهوية الاقتصادية، وحسابات النقد/البنك/المحفظة القديمة تبقى تفاصيل مرتبطة بـ`chartAccountId` ولا تتكرر أرصدتها. دليل اليومية للإضافة فقط على مستوى المستودع (تعديل/حذف القيد يرمي `APPEND_ONLY`)، وكل قيد يجب أن يتوازن بالوحدة الصغرى بلا ترقيع. القيود العكسية بتاريخ القيد الأصلي وتعكس أسطره تماماً. الأرقام `JE-000001` من عدّاد واحد وتُرحّل مع المعاملة عند الفشل. لا يُنشأ حساب ضريبة (`2300`) إلا عند وجود بيانات ضريبية قديمة (A3)، وحسابات الأصول الثابتة تُبذر فقط عند تفعيل الوحدة. **التقارير بقيت من المستندات حتى A3**، ولا يغيّر A1 أي مستند قديم.
- **قيمة المخزون والترحيل المخزني v5 A2:** `variants.valueMinor` هي الحقيقة، والمتوسط `valueMinor ÷ quantity` مشتق للعرض؛ كل حركة تحمل تغيّر القيمة والقيمة بعدها. توزيع الخصومات/التكاليف يستخدم `money.allocate` بالباقي الأكبر وبلا فرق يُرقّع. `posting.js` يرحّل الجانب المخزني فقط (COGS، المرتجعات، صافي المشتريات، فرق مرتجع الشراء إلى `5030`، الافتتاحي إلى `3030`، التسويات/الجرد إلى `5020`، تسوية التكلفة) داخل معاملة المستند، ويُربط كل قيد في `journalEntryIds[]`. الترحيل 4→5 يحافظ على القيم الإجمالية القديمة ولا ينشئ قيوداً.
- **ترحيل المستندات واعتماد التقارير v5 A3:** كل تدفقات المستندات عدا نطاق A4 ترحّل داخل معاملتها: المبيعات والذمم والدفعات المؤرخة، التحصيلات مع `2030` للزيادة، المرتجعات والاستبدال، المشتريات والموردون، المصروفات والموزّع، الرواتب والسلف، الملكية والتحويلات والإقفال اليومي. الإلغاء/التعديل بقيد عكسي مطابق بتاريخ الأصل، وتحديثات المصروفات تعكس ثم تعيد الترحيل. الترحيل 5→6 يعيد حساب مستحقات الشراء (استرداد النقد لا يخفض الذمة)، ويعبّئ `appliedMinor` القديم، ويعلّم إعادة التشغيل التي ينفذها الإقلاع. تقارير P&L/الميزانية لا تتحول إلى الدفتر إلا بعد `parityReport()` ناجح و`approveJournal()` صريح؛ `options.legacy` يبقي المستندات للمراجعة.
- **حدود المرحلة الحالية:** لا مزامنة ولا خادم ولا حساب سحابي ولا مسح عن بُعد. أُنجزت **L1–L10** و**v5 A1–A3** آلياً، مع بقاء بنود تحقق يدوي على هاتف فعلي (الأداء، فتح PDF/XLSX، مشاركة iOS) موضّحة في تقرير L10 وفي `docs/CHECKLIST.md`. ترقية عدة أجهزة موثّقة في `docs/UPGRADE_TO_V3_FULL.md`.

> **v5 A1 (2026-10-28):** أُضيفت نواة دفتر اليومية ودليل الحسابات (schema 4، dbVersion 7) مع 205/205 اختبار Node. **v5 A2 (2026-10-28):** أُضيفت قيمة المخزون المتتبعة وترحيل الجانب المخزني إلى الدفتر (schema 5، dbVersion 7) مع 219/219 اختبار Node. **v5 A3 (2026-10-29):** رُحّلت كل تدفقات المستندات عدا نطاق A4 إلى الدفتر، مع اعتماد تقارير P&L/الميزانية بعد مطابقة ناجحة، وإعادة تشغيل تاريخية (schema 6، dbVersion 7) مع 230/230 اختبار Node. لا توجد بعد شاشة دفتر يومية أو دليل حسابات (A6)، وخصم فاتورة البيع لا يوزّع على الأسطر بعد (v4 M7)، ووحدات A4 مؤجلة.
