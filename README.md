# بي ستور (Bee Store) — نظام المحاسبة والمخزون

## نظرة عامة

نظام متكامل لإدارة محل ملابس أطفال. يشمل المبيعات، المشتريات، المخزون، الزبائن، الموردين، المصاريف، الموظفين، والرواتب، والتقارير المالية.

## التشغيل

1. افتح مجلد المشروع
2. انقر نقراً مزدوجاً على ملف `index.html` (يفتح في Chrome أو Edge)
3. سيظهر معالج البداية لإعداد المتجر واختيار مجلد البيانات
4. ابدأ بإنشاء المنتجات والفواتير

## المتصفحات المدعومة

- **Chrome** (الأساسي - يعمل بشكل كامل مع الحفظ التلقائي)
- **Edge** (الأساسي - يعمل بشكل كامل مع الحفظ التلقائي)

في المتصفحات الأخرى سيظهر تحذير بأن الحفظ التلقائي في الملف غير متاح، ويمكن استخدام زر "تحميل نسخة احتياطية" للنسخ الاحتياطي اليدوي.

## اختصارات لوحة المفاتيح (صفحة الفاتورة)

| مفتاح | الوظيفة |
|---|---|
| F2 | تركيز حقل الباركود |
| F4 | إضافة دفعة / تركيز الدفع |
| Ctrl+Enter | حفظ الفاتورة |
| Escape | إغلاق الحوارات |

## نسخ احتياطي

### مكان البيانات
البيانات محفوظة في:
- **المتصفح (IndexedDB)**: مخزن العمل الأساسي
- **ملف JSON**: مرآة تلقائية في مجلد تختاره (مثل `BeeStore-Data`)
- **نسخ احتياطية موقوتة**: في نفس المجلد تحت `backups/` (يحتفظ بآخر 30 نسخة افتراضياً)

### الاستعادة
- من الإعدادات > النسخ الاحتياطي > استعادة من ملف
- أو تحميل ملف `db.json` مباشرة

### نصائح للحماية
- اختر مجلد بيانات جديد (مثل `BeeStore-Data`) لا مجلد نظام
- احتفظ بنسخة من مجلد البيانات على USB أو سحابة
- استخدم "تحميل نسخة احتياطية" دورياً في المتصفحات غير المدعومة

## القرارات التقنية

| القرار | الاختيار |
|---|---|
| التخزين الأساسي | IndexedDB |
| مرآة الملف | File System Access API |
| تنسيق المال | أعداد صحيحة بالوحدات الصغيرة (أغوروت) |
| أرقام الفواتير | عدادات داخل المعاملة مع بادئة |
| معرفات السجلات | عشوائية مسبوقة (مثل `prd_x7k2...`) |
| الأرقام المعروضة | غربية (0-9) |
| الحذف | Soft delete فقط (`status: void`) |
| العمليات معاملة | كل عملية نشر = معاملة واحدة |
| الباركود | EAN-13 متوافق (نطاق داخلي) |
| المخزون المتوسط | تكلفة متوسطة موزونة |
| توزيع خصم السطر على المرتجع | الخصم يُوزع تناسبياً: `خصم السطر × الكمية المرتجعة ÷ كمية السطر` (يُقرب لآخر وحدة) |
| الرواتب في الأرباح | استحقاق حسب شهر الراتب (مسودة ومدفوعة)، وسداد السلف لا يخفضها |
| رأس المال الافتتاحي | الأرصدة الافتتاحية الثابتة + حركات «افتتاحي» (مخزون مساهم به) بتاريخها |
| إلغاء المصاريف | إلغاء بسبب مع بقاء السجل (لا حذف نهائي) |
| أخطاء الواجهة | كل استدعاء يُرجع `{ok, error}` ولا يرمي استثناءً |

## الميزات الرئيسية

### نقطة البيع (POS)
- مسح الباركود / بحث بالاسم / تصفية بالتصنيف
- دمج الأصناف المتطابقة تلقائياً
- خصم سطر/فاتورة (مبلغ أو نسبة)
- دفع مقسم (نقدي، بطاقة، تحويل، محفظة)
- بيع آجل مع أقساط (أسبوعي/نصف شهري/شهري)
- طباعة A4 أو 80 مم حراري

### المخزون
- منتجات بأحجام وألوان (توليد شبكة)
- باركود تلقائي / يدوي
- تسوية مخزون، جرد، استيراد CSV
- تنبيه مخزون منخفض

### الحسابات والتقارير
- قائمة الدخل (P&L) مع تكلفة موزونة
- تقارير مبيعات (يومي، زبون، طريقة دفع)
- تقييم المخزون (تكلفة/بيع)
- ذمم زبائن/موردين بالتقادم
- ميزانية مبسطة (أصول = خصوم + حقوق)
- إغلاق يومي، مصاريف، رواتب
- تصدير CSV (مع BOM للعربية)

### أمان البيانات
- قفل تبويب واحد (Web Locks API)
- حفظ تلقائي عند إغلاق التبويب
- استمرارية التخزين (`navigator.storage.persist`)
- ترحيل إصدارات البيانات تلقائياً

## الإقفال الشهري (خطوة بخطوة)

1. من الترويسة اختر الشهر (◀ الشهر ▶) — كل الصفحات تعرض نطاقه، والمُقفل يحمل شارة 🔒.
2. **ولّد المصاريف الشهرية**: ستظهر رسالة تنبيه في الرئيسية إن وُجدت مصاريف ناقصة — اضغط "إنشاؤها الآن".
3. **جهّز الرواتب وادفعها** من صفحة الموظفون والرواتب (غير المدفوع يبقى مستحقاً على الشهر — وهذا صحيح محاسبياً).
4. (اختياري) نفّذ **جرد المخزون**.
5. افتح صفحة **إقفال الشهور**: راجع قائمة الفحص وتقرير الشهر، أصلح أي خطأ، ثم اضغط **إقفال الشهر** (يُؤخذ نسخة احتياطية تلقائياً قبل القفل).
6. الشهر المُقفل **ممنوع** تعديله — أي تصحيح يُسجَّل في الشهر الحالي (مرتجع/تسوية/مصروف بتاريخ اليوم)، أو أعد فتح **آخر شهر مُقفل فقط** (بتأكيد كتابي) من نفس الصفحة.
7. ملاحظة: شراء البضاعة **لا يُنقص** ربح الشهر (يتحول لنقد → مخزون)؛ الربح ينقص عند البيع. تقرير "الربح ⇄ النقد" يوضح الفرق.
