## 2026-10-24 — v3-Lite L1: PWA، العمل دون إنترنت، تحديث آمن، ونشر HTTPS
- **هوية PWA**: `manifest.json` عربي RTL (`lang: ar`, `dir: rtl`, `display: standalone`, `start_url`/`scope` = `./`، لون `#F5B700`)، وأيقونات 192/512 + maskable 512 + Apple 180 مولّدة من `icons/icon.svg` و`icons/icon-maskable.svg` عبر Chromium (بدون ImageMagick). ربط المانيفست وأيقونة Apple و`theme-color` في `index.html`.
- **Service Worker وقائمة كاش صريحة**: `sw.js` يخزّن هيكل التطبيق فقط (84 ملفاً، ~1.6 MB) بنمط cache-first، مع fallback إلى `index.html` لأي تنقّل. لا يخزّن بيانات أو نسخاً احتياطية أو طلبات خارجية. `CACHE_VERSION` = بصمة SHA-256 لمحتوى الملفات، ويُولَّد عبر `scripts/build-sw-list.js` (ممنوع تعديله يدوياً). `tests/test-sw.js` يفشل إذا كانت القائمة أو النسخة قديمة.
- **تحديث آمن لا يقطع الفاتورة**: لا `skipWaiting` أثناء التثبيت. الصفحة تعرض شريط **«تحديث متوفر»**، وعند ضغط المستخدم فقط ترسل `{type:'SKIP_WAITING'}` بعد فحص الحالة: سلة POS فارغة، لا حفظ جارٍ، لا نافذة/معالج **ظاهر**، لا إغلاق يومي. عند الرفض تظهر رسالة «احفظ الفاتورة أو أغلق النوافذ المفتوحة قبل التحديث». بعد التفعيل يُحذف الكاش القديم فقط، ويُعاد تحميل التطبيق مرة واحدة دون مسح IndexedDB.
- **إصلاح حرج اكتشفه اختبار التحديث**: معالج البداية يبقى في DOM مخفياً بعد الانتهاء، وكان يُحسب كنافذة مفتوحة فيمنع كل تحديث. صار فحص النوافذ يعتمد على الظهور الفعلي (`getComputedStyle`)، مع بقاء الحوارات/الماسح/الإغلاق مانعة.
- **تثبيت phone-first**: شريط تثبيت داخل التطبيق، ودليل عربي مفصّل (أندرويد Chrome / آيفون Safari / كمبيوتر) مع ملاحظة أن آيفون يتطلب Safari. زر «تثبيت» يستخدم `beforeinstallprompt` عند توفره، ويعود للدليل عند رفض المتصفح أو غياب الحدث. إزالة التحذير الخاطئ عند غياب File System Access API (كان يظهر على الهواتف رغم أن التطبيق يعمل)، وتخطي خطوة مجلد البيانات تلقائياً على الهاتف.
- **تبويب الإعدادات → البيانات**: حالة التخزين الدائم + المساحة المستخدمة/الكلية + زر `navigator.storage.persist()`، حالة التثبيت والعمل دون إنترنت، نسخة التطبيق/الكاش/مخطط البيانات، زر التحقق من التحديث وتطبيقه، وقائمة لقطات الأمان المحلية مع تنزيلها.
- **لقطات ما قبل الترحيل**: `js/services/snapshots.js` يستخدم قاعدة IndexedDB منفصلة `beestore-snapshots` (مخزن بيانات + مخزن وصف) ويحتفظ بآخر 10 لقطات. `app.js` ينشئ لقطة `pre-migration` قبل `migrations.migrate`؛ إذا فشلت اللقطة لا يُرحَّل البيانات. إصلاح `IdbRepository._loadAll()` ليعرض `schemaVersion` المخزّن فعلاً بدل نسخة الكود، حتى لا تُتخطى الترحيلات القديمة.
- **أمان الواجهة**: CSP في `index.html` بـ `script-src 'self'` و`object-src 'none'` و`worker-src 'self'` و`style-src 'self' 'unsafe-inline'` (لأن الواجهة تستخدم `style` ديناميكياً). حُذفت كل معالجات `onclick` المضمّنة (24) واستُبدلت بتفويض حدث واحد لـ `[data-route]`، مع إصلاح فتح السايد بار في المتاجر المنشأة عبر المعالج (كان يعتمد على `onclick` المحذوف).
- **الاختبارات**: جديدة `tests/test-pwa.js` (فحص التحديث الآمن، بيئة SW، التخزين)، `tests/test-sw.js` (تطابق قائمة الكاش/البصمة، المانيفست والأيقونات، CSP، غياب inline handlers، منع skipWaiting التلقائي)، `tests/test-snapshots.js` (الاحتفاظ/العدّ). المجموع **144/144** ناجح.
- **تحقق متصفح فعلي**: 84 ملفاً في الكاش، Service Worker يتحكم بالصفحة، إعادة تحميل دون إنترنت من الكاش، شريط التثبيت والدليل، تبويب البيانات، لقطة IndexedDB حقيقية، وتدفق تحديث كامل (ظهور الشريط → منعه أثناء فاتورة → تطبيقه بعد إفراغ السلة → النسخة الجديدة نشطة والكاش القديم محذوف) بلا أخطاء Console.
- **النشر والتوثيق**: `docs/DEPLOY_AR.md` (نشر GitHub Pages خطوة بخطوة، التحديث، تحذير العنوان/الأصل، تثبيت أندرويد/آيفون، بديل Cloudflare Pages، استكشاف الأخطاء)، وتحديث `README.md`، `CLAUDE.md`، `docs/MAP.md`، `docs/CHECKLIST.md`. الاستضافة الأساسية GitHub Pages مع توضيح شروطها (ليست للمتاجر الإلكترونية/SaaS) وبديل Cloudflare Pages للاستخدام التجاري.
