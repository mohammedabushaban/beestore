# نشر بي ستور على الإنترنت — دليل عربي خطوة بخطوة

**الإصدار:** BeeStore v3-Lite (L1 — PWA والنشر)  
**آخر تحديث للدليل:** 2026-10-24  
**الجمهور:** صاحب المحل أو من يساعده تقنياً. لا تحتاج خادماً ولا قاعدة بيانات ولا حساباً في خدمة سحابية.

---

## 1. ما الذي ننشره؟

بي ستور تطبيق ويب ثابت (ملفات HTML/CSS/JS فقط). الاستضافة تعطي الهاتف **ملفات التطبيق** عبر HTTPS، ولا تحفظ أي بيانات. كل البيانات (الفواتير، المنتجات، الزبائن…) تبقى داخل متصفح الهاتف في **IndexedDB**.

هذا يعني:

- لا يوجد خادم تطبيق، ولا API، ولا قاعدة بيانات على الإنترنت.
- لا تُرسل بيانات المحل إلى الاستضافة.
- الاستضافة ترى فقط طلبات تحميل الملفات (مثل أي موقع ثابت).
- التطبيق يعمل بعد التحميل الأول **دون إنترنت**.

> **لا تفتح `index.html` بالنقر المزدوج.** فتح الملف مباشرة (`file://`) يمنع IndexedDB ويعطّل التثبيت والعمل دون إنترنت. استخدم دائماً رابط `https` المنشور (أو `http://localhost` أثناء التطوير فقط).

---

## 2. اختيار الاستضافة

### الاختيار الأساسي: GitHub Pages

اخترناه لأن المستودع موجود أصلاً على GitHub، ولا يحتاج حساباً إضافياً ولا خطوة بناء، ويدعم HTTPS والمسارات النسبية (مجلد فرعي) مجاناً.

#### شروط GitHub Pages الحالية (تحقق منها في 2026-10-24)

هذه حدود GitHub المنشورة، وقد تتغير؛ راجع الرابط في نهاية القسم:

| البند | الحد |
|---|---|
| حجم المستودع الموصى به | 1 GB |
| حجم الموقع المنشور | 1 GB كحد أقصى |
| النطاق الترددي | 100 GB شهرياً (حد «لطيف»/soft) |
| عدد عمليات البناء | 10 في الساعة (لا ينطبق عند البناء بـ GitHub Actions) |
| مهلة النشر | 10 دقائق |
| موقع مستخدم/منظمة واحد | واحد لكل حساب |

**قيود الاستخدام المهمة:** تقول GitHub إن Pages **ليس** خدمة استضافة مجانية لتشغيل متجر إلكتروني أو موقع تجاري أو برنامج SaaS. بي ستور أداة محاسبية داخلية لمحل واحد، ولا يبيع عبر الإنترنت ولا يقدّم خدمة SaaS، والاستضافة لا تتعامل مع أي بيانات أو مدفوعات. هذا يجعله أقرب لاستخدام مقبول، لكنه ليس رأياً قانونياً. إذا أردت تجنّب أي التباس تجاري، استخدم **Cloudflare Pages** (القسم 10) فهي تسمح بالاستخدام التجاري.

- الصفحات من مستودع **عام** هي الأبسط. الصفحات من مستودع **خاص** تتطلب عادةً خطة GitHub مدفوعة (Pro/Team/Enterprise).
- لا تضع في المستودع أي مفاتيح أو أسرار؛ التطبيق ثابت بالكامل.

المرجع: <https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits>

## 3. النشر الأول على GitHub Pages (خطوات مرقمة)

### قبل البدء

1. ثبّت Git على جهازك، وسجّل الدخول إلى GitHub.
2. تأكد أن مشروع BeeStore موجود في مستودع GitHub (مثلاً `username/BeeStore`).
3. تأكد أن الفرع الرئيسي اسمه `main` (أو عدّل اسم الفرع في الخطوة 6).
4. شغّل الاختبارات محلياً قبل الرفع:

```bash
cd BeeStore
node scripts/build-sw-list.js
node --test tests/*.js
```

يجب أن تنتهي آخر سطر بـ `fail 0`. لا تنشر نسخة اختباراتها حمراء.

### الرفع

5. ارفع آخر نسخة إلى GitHub:

```bash
git add -A
git commit -m "BeeStore v3-Lite L1: PWA, offline shell, safe updates"
git push origin main
```

### تفعيل Pages

6. افتح المستودع على GitHub → **Settings** (الإعدادات).
7. من القائمة الجانبية اختر **Pages**.
8. تحت **Build and deployment** → **Source** اختر **Deploy from a branch**.
9. تحت **Branch** اختر `main`، وتحت **Folder** اختر **`/ (root)`**.
10. اضغط **Save**.
11. انتظر من دقيقة إلى ثلاث دقائق. ستظهر رسالة أعلى الصفحة تقول إن النشر جارٍ ثم يعطيك الرابط.
12. انسخ الرابط. سيكون أحد الشكلين:

- موقع مستخدم: `https://<username>.github.io/` (إذا كان اسم المستودع `<username>.github.io`).
- موقع مشروع: `https://<username>.github.io/<repo>/`.

المسارات النسبية في التطبيق (`./`) تعمل في الحالتين.

13. افتح الرابط على الهاتف في Chrome (أندرويد) أو Safari (آيفون). يجب أن تظهر شاشة البداية، لا قائمة ملفات ولا خطأ 404.

### أول تشغيل

14. أدخل اسم المتجر والهاتف والعنوان وتاريخ بدء الاستخدام.
15. على الهاتف تُتخطّى خطوة «مجلد البيانات» تلقائياً لأنها ميزة كمبيوتر فقط. اختر **البدء بدون بيانات** أو **تحميل بيانات تجريبية**.
16. اذهب إلى **الإعدادات → البيانات** وتأكد أن:
    - «التطبيق محفوظ على الهاتف ويعمل دون إنترنت» تظهر بعلامة ✅.
    - «نسخة الكاش» تظهر (مثل `beestore-v3-lite-xxxxxxxxxxxx`).
    - زر «طلب تخزين دائم» موجود (اضغطه مرة واحدة؛ قد يرفض المتصفح، وهذا لا يمنع العمل).

## 4. ماذا يحدث عند أول فتح؟

1. المتصفح يحمّل ملفات التطبيق من الاستضافة.
2. service worker (`sw.js`) يحفظ نسخة من هيكل التطبيق (84 ملفاً، وحوالي 1.6 MB) في **Cache Storage**.
3. عند إعادة الفتح دون إنترنت، يقدّم الـ service worker ملفات التطبيق من الكاش، وتُقرأ البيانات من IndexedDB.
4. لا يُحفظ أي شيء من بيانات المحل في الكاش؛ الكاش لملفات التطبيق فقط.

> **مهم:** افتح التطبيق مرة واحدة على الأقل بعد التثبيت وأنت متصل بالإنترنت، حتى يكتمل حفظ النسخة المحلية.

## 5. تحديث التطبيق لاحقاً (خطوات مرقمة)

لا تعدّل `sw.js` يدوياً أبداً. قائمة الملفات ونسخة الكاش تُولَّد آلياً.

1. عدّل ملفات التطبيق (JS/CSS/HTML/أيقونات…).
2. أعد توليد قائمة الكاش:

```bash
node scripts/build-sw-list.js
```

سيطبع عدد الملفات ونسخة كاش جديدة، مثل:

```
files:   84
version: beestore-v3-lite-xxxxxxxxxxxx
```

3. شغّل الاختبارات:

```bash
node --test tests/*.js
```

اختبار `tests/test-sw.js` يفشل إذا نسيت تشغيل السكربت، لأن نسخة الكاش لا تطابق محتوى الملفات. لا تنشر عند وجود فشل.

4. ارفع التغييرات:

```bash
git add -A
git commit -m "update: ..."
git push origin main
```

5. انتظر انتهاء نشر GitHub Pages (عادة 1–3 دقائق).
6. افتح التطبيق على الهاتف **وأنت متصل بالإنترنت**. سيظهر شريط **«تحديث متوفر»** بعد لحظات.
7. لا تضغط «تحديث الآن» إذا كنت:
   - في منتصف فاتورة (السلة غير فارغة)،
   - أو تحفظ فاتورة،
   - أو نافذة/معالج مفتوح،
   - أو في إغلاق يومي.
   التطبيق يرفض التحديث في هذه الحالات ويظهر رسالة عربية. أنهِ عملك أولاً.
8. اضغط **«تحديث الآن»**. سيُعاد تحميل التطبيق مرة واحدة، ثم يعمل بالنسخة الجديدة. **البيانات المحفوظة لا تُحذف.**
9. إذا لم يظهر الشريط:
   - أغلق التطبيق من قائمة التطبيقات وأعد فتحه، أو
   - **الإعدادات → البيانات → التحقق من التحديث**، أو
   - انتظر بضع دقائق (قد تكون نسخة GitHub Pages القديمة ما تزال في شبكة التوزيع).
10. بعد التحديث، افتح **الإعدادات → البيانات** وتأكد أن «نسخة الكاش» تغيّرت. هذا دليل على أن النسخة الجديدة هي العاملة.

### ماذا يحدث للكاش القديم؟

عند تفعيل النسخة الجديدة، يحذف الـ service worker كل كاش بي ستور قديم ويُبقي النسخة الحالية فقط. لا يمسّ IndexedDB ولا النسخ الاحتياطية.

## 6. تحذير عنوان الموقع والبيانات (اقرأه قبل تغيير الرابط)

بيانات IndexedDB مرتبطة بـ **أصل الموقع (origin)**، أي:

```
المخطط (https) + النطاق (username.github.io) + المنفذ (443 افتراضياً)
```

وليست مرتبطة بمسار المجلد. لذلك:

| التغيير | ماذا يحدث للبيانات؟ |
|---|---|
| تغيير المسار على نفس النطاق (مثل إعادة تسمية المستودع) | نفس قاعدة البيانات (لأن الأصل لم يتغير). لكن قد تشارك البيانات مع مشروع آخر على نفس النطاق. |
| الانتقال من `username.github.io` إلى نطاق مخصص | **قاعدة جديدة فارغة** |
| الانتقال إلى `project.pages.dev` (Cloudflare) | **قاعدة جديدة فارغة** |
| تغيير `http` إلى `https` أو العكس | **قاعدة جديدة فارغة** |
| تغيير منفذ `localhost` (مثلاً 8080 → 5500) | **قاعدة جديدة فارغة** |

### القواعد العملية

1. اختر عنواناً واحداً والتزم به.
2. لا تفتح نسختين من التطبيق على أصلين مختلفين وتتوقع رؤية نفس البيانات.
3. قبل أي انتقال:
   - من العنوان القديم: **الإعدادات → النسخ الاحتياطي → تحميل نسخة احتياطية**.
   - من العنوان الجديد: **الإعدادات → النسخ الاحتياطي → استعادة من ملف** واختر الملف.
4. لا تحذف بيانات الموقع من إعدادات المتصفح («مسح بيانات المواقع»)؛ هذا يحذف IndexedDB. استخدم النسخ الاحتياطي بدلاً من ذلك.
5. إذا كنت تستخدم GitHub Pages لمشروع واحد فقط على حسابك، فأنت في أمان من تداخل المسارات. لا تنشر نسخة ثانية من بي ستور على نفس `username.github.io` بمسار آخر؛ ستشارك نفس قاعدة البيانات `beestore-db`.

## 7. تثبيت التطبيق على الهاتف

### أندرويد — Chrome

1. افتح رابط التطبيق في Chrome.
2. إما اضغط زر **«تثبيت»** في الشريط السفلي داخل التطبيق، أو:
3. اضغط قائمة النقاط الثلاث **⋮** أعلى المتصفح.
4. اختر **«تثبيت التطبيق»** أو **«إضافة إلى الشاشة الرئيسية»**.
5. اضغط **«تثبيت»**.
6. افتح بي ستور من أيقونة الشاشة الرئيسية. سيعمل بدون شريط المتصفح.

### آيفون — Safari

1. افتح الرابط في **Safari** تحديداً. لا تفتحه داخل واتساب أو فيسبوك أو Chrome على iOS؛ هذه التطبيقات لا تستطيع تثبيت PWA.
2. اضغط زر **المشاركة** (المربع مع السهم).
3. مرّر واختر **«إضافة إلى الشاشة الرئيسية»**.
4. اضغط **«إضافة»**.
5. افتح التطبيق من الأيقونة.

### الكمبيوتر — Chrome/Edge

- اضغط أيقونة التثبيت بجانب شريط العنوان، أو قائمة المتصفح → **«تثبيت بي ستور»**.

### بعد التثبيت

- افتح التطبيق مرة واحدة وأنت متصل حتى يكتمل الكاش.
- جرّب **وضع الطيران** ثم أعد فتح التطبيق؛ يجب أن تظهر البيانات.
- لا تعتمد على التثبيت وحده كنسخة احتياطية. التثبيت يمنع حذف البيانات «بشكل تلقائي» عند ضغط المساحة فقط إذا كان التخزين الدائم مفعّلاً، وهذا ليس مضموناً.

## 8. العمل دون إنترنت

1. بعد أول فتح ناجح، اذهب إلى **الإعدادات → البيانات** وتأكد من ظهور «التطبيق محفوظ على الهاتف ويعمل دون إنترنت».
2. فعّل وضع الطيران.
3. أغلق التطبيق من قائمة التطبيقات (ليس فقط تصغيراً) ثم افتحه من الأيقونة.
4. يجب أن تفتح الصفحة الرئيسية وتعمل الفواتير والمنتجات.
5. أعد الاتصال. لا تحتاج إلى مزامنة؛ لا يوجد خادم.

**ملاحظات:**

- الكاميرا تحتاج HTTPS (أو localhost). GitHub Pages وCloudflare يوفّران HTTPS.
- قارئ الباركود USB/Bluetooth يعمل كإدخال لوحة مفاتيح، ولا يتأثر بالعمل دون إنترنت.
- إذا مسحت بيانات المتصفح أو أعدت تثبيت التطبيق من الصفر، ستحتاج إلى استعادة نسخة احتياطية.

## 9. التحقق بعد النشر (قائمة سريعة)

- [ ] الرابط يبدأ بـ `https://` وتظهر أيقونة القفل.
- [ ] الصفحة تفتح ولا تظهر قائمة ملفات أو 404.
- [ ] اسم التطبيق «بي ستور» يظهر في شاشة البداية/الأيقونة.
- [ ] **الإعدادات → البيانات** تعرض نسخة الكاش و«التطبيق محفوظ…».
- [ ] التثبيت على الشاشة الرئيسية يعمل (أندرويد/آيفون).
- [ ] بعد فتح واحد متصل، وضع الطيران لا يمنع فتح التطبيق.
- [ ] إنشاء فاتورة تجريبية دون إنترنت ثم إعادة فتح التطبيق: الفاتورة موجودة.
- [ ] حفظ فاتورة ثم تحديث التطبيق: لا تظهر رسالة فقدان بيانات، والفاتورة موجودة.
- [ ] محاولة التحديث والسلة غير فارغة: تظهر رسالة «احفظ الفاتورة أو أغلق النوافذ المفتوحة قبل التحديث».
- [ ] لا توجد أخطاء CSP في Console (F12 → Console).
- [ ] قارئ الباركود USB/Bluetooth ما زال يضيف الأصناف ولا يحفظ الفاتورة بـ Enter.
- [ ] الكاميرا تعمل على أندرويد Chrome وآيفون Safari (إن كنت تستخدم المسح).
- [ ] بعد تحديث جديد: «نسخة الكاش» تغيّرت، والكاش القديم اختفى (Application → Cache Storage).

## 10. بديل: Cloudflare Pages (إن أردت استخداماً تجارياً واضحاً)

Cloudflare Pages استضافة ثابتة مجانية مع HTTPS، وتسمح بالاستخدام التجاري (راجع حدود الخطة الحالية). مناسبة إذا كان GitHub Pages غير مناسب لسياسة الاستخدام.

### النشر من GitHub

1. أنشئ حساب Cloudflare.
2. من لوحة التحكم: **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
3. اختر مستودع BeeStore وامنح الصلاحية.
4. الإعدادات:
   - **Framework preset:** None
   - **Build command:** اتركه فارغاً
   - **Build output directory:** `/` (جذر المستودع)
5. اضغط **Save and Deploy**.
6. ستحصل على رابط مثل `https://beestore.pages.dev/`.

### أو الرفع المباشر (بدون ربط Git)

1. من **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
2. اسحب مجلد المشروع (أو حدد الملفات) ثم انشر.
3. عند كل تحديث، أعد الرفع يدوياً — أو اربط Git لتحديث تلقائي.

**مهم:** رابط `pages.dev` أصل مختلف عن `github.io`. إذا انتقلت بعد بدء العمل، صدّر نسخة احتياطية من العنوان القديم واستوردها في الجديد.

### بديل آخر: Netlify

- اذهب إلى <https://app.netlify.com/drop> واسحب مجلد المشروع. ستحصل على HTTPS مجاني.
- التحديثات اليدوية تتطلب إعادة السحب؛ اربط Git إن أردت نشراً تلقائياً.
- راجع حدود الخطة المجانية الحالية قبل الاعتماد عليها.

## 11. استكشاف الأخطاء

| المشكلة | السبب المرجح | الحل |
|---|---|---|
| 404 عند فتح الرابط | لم يُفعّل Pages، أو الفرع/المجلد خطأ | Settings → Pages، تأكد من `main` و`/ (root)`، وانتظر النشر |
| الصفحة بيضاء | فتحت `file://` أو حجب المتصفح السكربتات | افتح رابط HTTPS، وتحقق من Console |
| لا يظهر زر التثبيت | المتصفح لا يدعم `beforeinstallprompt` (آيفون) | استخدم دليل التثبيت داخل التطبيق: Safari → مشاركة → إضافة إلى الشاشة الرئيسية |
| «التخزين الدائم غير مفعّل» | المتصفح رفض الطلب أو لا يدعمه | اضغط «طلب تخزين دائم»؛ إن رفض، احتفظ بنسخ احتياطية دورية |
| «تحديث متوفر» لا يظهر | نسخة قديمة من `sw.js` في الشبكة، أو لم يُشغّل سكربت الكاش | أعد فتح التطبيق، أو Settings → البيانات → التحقق من التحديث، وتأكد من تشغيل `node scripts/build-sw-list.js` قبل الرفع |
| بعد التحديث اختفت البيانات | غيّرت الأصل (نطاق/منفذ/بروتوكول) | ارجع للعنوان القديم واستعد النسخة الاحتياطية، أو استوردها في العنوان الجديد |
| «تعذّر فتح قاعدة البيانات» | فتحت `index.html` مباشرة | استخدم خادم HTTPS أو `python3 -m http.server` على localhost |
| الكاميرا لا تعمل | سياق غير آمن (http على LAN) أو إذن مرفوض | استخدم HTTPS، أو localhost، وامنح إذن الكاميرا |
| بطء أول فتح | تحميل 84 ملفاً (~1.6 MB) | طبيعي مرة واحدة؛ بعدها يعمل من الكاش |

### لا تفعل هذه الأشياء

- لا تحذف «بيانات الموقع» من إعدادات المتصفح؛ هذا يحذف قاعدة البيانات.
- لا تفتح التطبيق من عنوانين مختلفين وتكتب بيانات في كليهما.
- لا تعدّل `sw.js` يدوياً؛ استخدم `node scripts/build-sw-list.js`.
- لا تنشر قبل نجاح `node --test tests/*.js`.
- لا تضع أسراراً أو بيانات عملاء في المستودع.

## 12. النسخ الاحتياطي في L1

في هذه المرحلة (L1) توجد:

- **تنزيل نسخة احتياطية** من **الإعدادات → النسخ الاحتياطي** (ملف JSON).
- **مجلد بيانات تلقائي** على الكمبيوتر فقط (File System Access API) مع نسخ موقوتة.
- **لقطات محلية** قبل تحديث مخطط البيانات، تُعرض في **الإعدادات → البيانات** ويمكن تنزيلها.

**لا يكفي أي منها وحده.** احفظ ملف النسخة الاحتياطية خارج الهاتف دورياً (Google Drive، واتساب، بريد، USB). زر المشاركة إلى Drive/واتساب ضمن خطة L2.

## 13. الخلاصة

- الاستضافة تخدم الملفات فقط؛ البيانات على الهاتف.

- حافظ على عنوان واحد، وخذ نسخة احتياطية قبل أي انتقال.
